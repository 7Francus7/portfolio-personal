# Checklist de campo — Sodería Nico

> Objetivo: volver de **una sola visita** con todo el material que hoy bloquea
> el 60 % del valor del portfolio. Nada de esto se puede generar desde el
> repositorio.
>
> Separado por **cómo se consigue cada cosa**, porque eso determina qué hacés
> vos solo, qué necesitás preguntar y qué requiere que alguien firme.

Marcá con `[x]` a medida que lo conseguís. Los ítems **P0** son los que
bloquean publicar el caso o las notas.

---

## Antes de ir

- [ ] Avisar al dueño con qué vas y para qué (portfolio público).
- [ ] Llevar el teléfono con batería y espacio libre (las capturas pesan).
- [ ] Poner el teléfono en **No molestar**: las notificaciones arruinan capturas.
- [ ] Si el sistema tiene datos sensibles, definir de antemano si se anonimizan
      en el momento o después. **Decidilo antes de sacar la primera captura.**
- [ ] Llevar impresa o a mano la sección "Lo que debe responder el dueño".

## A · Lo que podés obtener observando

No necesitás que nadie te conteste. Es cuestión de mirar y registrar.

### A1 · Capturas del sistema — **P0**

Las seis que el caso ya tiene reservadas en `content/cases/soderia-nico.ts`.
Cada una debe mostrar **datos reales o realistas**, nunca "Lorem" ni tablas
vacías: una captura con datos de prueba comunica lo mismo que ninguna captura.

- [ ] **Panel de reparto con una ruta cargada.** Un día real, con varias
      paradas. Es la pantalla que sostiene todo el caso.
- [ ] **POS a mitad de una venta a cuenta.** Capturada *durante* la carga, no
      con el formulario vacío: se tiene que ver el flujo, no el layout.
- [ ] **Ficha de cliente con cuenta corriente.** Que se vea deuda en plata y
      envases adeudados en la misma vista — es la decisión de producto central.
- [ ] **Tracking de envases / dispensers.** Con dueño y ubicación visibles.
- [ ] **Cierre de caja o reporte diario.** Con un número calculado.
- [ ] **Vista mobile.** Capturada en un teléfono real, no con el simulador del
      navegador: el ancho, las fuentes y el teclado se ven distintos.

Para cada una:
- [ ] Resolución alta (captura nativa, no foto de la pantalla).
- [ ] Sin barras de notificaciones ni pestañas del navegador con datos ajenos.
- [ ] Anonimizar nombres/teléfonos reales si no hay autorización (ver §D).

### A2 · Fotos del proceso anterior y del contexto — **P0**

Esto es lo que ningún otro portfolio tiene. Vale más que cualquier captura.

- [ ] **El cuaderno, la planilla o el papel** donde se anotaba antes. Si todavía
      existe, fotografiarlo tal cual está, con las marcas de uso.
- [ ] **El camión de reparto**, cargado si se puede.
- [ ] **Los sifones y dispensers** — el activo que se perdía sin rastro.
- [ ] **El local o depósito**, plano general.
- [ ] **Alguien usando el sistema** durante un reparto o una venta (requiere
      autorización, ver §D).

> El "antes y después" en fotos —cuaderno manchado vs. pantalla— es la pieza de
> mayor impacto de todo el material. Si conseguís una sola cosa, que sea esta.

### A3 · Observación de la operación

- [ ] Qué tareas **siguen siendo manuales** hoy. Listarlas sin juzgar: van al
      caso como honestidad, no como defecto.
- [ ] Dónde se **traba** alguien al usar el sistema. Anotalo textual.
- [ ] Cuántas personas lo usan y con qué rol.
- [ ] Desde qué dispositivo se usa realmente.

## B · Lo que debe responder el dueño

Preguntas concretas. Llevalas escritas: en el momento uno se olvida.

### B1 · Historia y adopción — **P0**

- [ ] ¿En qué **mes y año** empezaron a usarlo?
- [ ] ¿Qué usaban antes, exactamente? (cuaderno, Excel, WhatsApp, memoria)
- [ ] ¿Qué fue lo primero que dejaron de hacer a mano?
- [ ] ¿Hubo algo que probaron y no funcionó?

### B2 · Escala de la operación — **P0**

Números aproximados alcanzan. Pedile rangos si no está seguro.

- [ ] ¿Cuántos **clientes con cuenta corriente** manejan?
- [ ] ¿Cuántos **repartos por día** o por semana?
- [ ] ¿Cuántos **envases** circulan aproximadamente?

### B3 · Antes y después — **P0**

Es lo que convierte el caso de "hice un sistema" a "resolví un problema".

- [ ] ¿Cuánto tardaba el **cierre de caja** antes? ¿Y ahora?
- [ ] ¿Cómo sabían antes **quién debía plata**? ¿Cuánto tardaban en averiguarlo?
- [ ] ¿Qué pasaba cuando un cliente **discutía una deuda**?
- [ ] ¿Perdían envases? ¿Tienen idea de cuántos, antes y ahora?

### B4 · Decisiones que habilitó el sistema

Esto es lo que demuestra impacto de negocio, no solo ahorro de tiempo.

- [ ] ¿Tomaron alguna **decisión concreta** mirando el sistema que antes no
      podían tomar? (cortarle el crédito a alguien, cambiar una ruta, ajustar
      un precio, reclamar envases)
- [ ] ¿Hay algún **caso puntual** que recuerde? Pedile la anécdota completa.

### B5 · Testimonio — **P0**

- [ ] Grabalo o anotalo **textual**. No lo reescribas después en "lenguaje de
      marketing": lo que lo hace creíble es que suene a él.
- [ ] Que mencione un problema concreto, no un elogio genérico.
- [ ] Nombre y rol de quien lo dice.

> Pregunta que suele funcionar: *"Si un conocido tuyo con un negocio parecido
> te pregunta si vale la pena, ¿qué le decís?"*

## C · Lo que hay que medir o consultar en el sistema

No lo sabe el dueño de memoria: sale de mirar los datos.

- [ ] **Cantidad de clientes** cargados (consulta o conteo en pantalla).
- [ ] **Cantidad de movimientos** de cuenta corriente registrados.
- [ ] **Envases actualmente prestados** y a cuántos clientes.
- [ ] **Antigüedad del primer registro** — confirma la fecha de inicio de uso
      mejor que la memoria.
- [ ] **Tiempo real de carga de una venta**: cronometralo. Es el número que
      sostiene "cargar una venta tarda menos que anotarla en papel", que hoy el
      sitio afirma sin medición.

> Cualquier número que salga de acá va al caso con su fuente. Los que salgan de
> una estimación del dueño se publican **declarados como estimación**.

## D · Lo que requiere autorización escrita

Sin esto no se publica. Alcanza un WhatsApp con respuesta afirmativa, pero
tiene que quedar por escrito.

- [ ] **Nombrar el negocio** en el portfolio, con su nombre comercial real.
- [ ] **Publicar las capturas** del sistema, aclarando si van con datos reales
      o anonimizados.
- [ ] **Publicar el testimonio** con nombre y rol.
- [ ] **Publicar fotos del local, el camión o los envases.**
- [ ] **Publicar fotos donde aparezcan personas** (autorización de cada una).
- [ ] **Publicar los números** de escala y de antes/después.

> Guardá la autorización en un lugar recuperable y anotá la fecha en
> `docs/implementation/fase-3b-afirmaciones-verificadas.md`.

```bash
npm run verify        # lint + typecheck + build + smoke
npm run check:demos   # revalida las demos públicas declaradas
```

## Qué desbloquea cada bloque

| Bloque | Desbloquea |
|---|---|
| A1 capturas | El caso deja de ser 100 % tipográfico — barrera de conversión #1 tras el idioma |
| A2 fotos | El "antes y después" real, la pieza más diferenciada del portfolio |
| B2 + B3 + C | `resultados[]` deja de estar vacío; el sitio pasa de afirmar impacto a mostrarlo |
| B5 | Primer testimonio del portfolio |
| B4 | La nota sobre decisiones de negocio, hoy sin ejemplo concreto |
| D | Todo lo anterior se puede publicar |
